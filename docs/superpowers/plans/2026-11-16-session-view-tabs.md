# Session View Tabs and "Move to App" Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One session view with `Terminal | Info` tabs, and a safe "Move to app" that ends an idle external `claude` and resumes the session in an app terminal.

**Architecture:** Core (`station_core`) learns which live sessions are movable and whether they are idle (status + running agents). A new Tauri command `adopt_session` re-checks idleness against a fresh registry read, terminates the verified pid through `platform`, waits until the session is gone and spawns the existing resume PTY with a source captured before the kill. The UI keeps `{ terminal }` as the Terminal tab of an in-app session, adds `{ session, tab, terminal? }` for the rest, and resolves the view against the snapshot so it follows the terminal.

**Tech Stack:** Rust (workspace `core`, `src-tauri`, Tauri 2, `windows-sys`, `libc`), React + TypeScript + Vitest (`ui`).

**Spec:** `docs/superpowers/specs/2026-11-16-session-view-tabs-design.md`

## Global Constraints

- No AI attribution lines in any commit message (machine-wide rule).
- Commit only files the task touched; `src-tauri/permissions/autogenerated/*.toml` already have unrelated local edits — stage only the new command's toml.
- Every new UI string key and every new Rust error code exists, non-empty, in all nine dictionaries `ui/src/i18n/{tr,en,az,de,es,fr,ru,zh}.ts` (+ any other file in that folder); `ui/src/i18n/i18n.test.ts` enforces it. Error codes are listed in `errors::ALL`.
- Only the session id goes from UI to backend; pid, folder, command line are derived in the backend.
- Movable = registry `kind == "interactive"` AND `entrypoint == "cli"`. Missing fields = not movable.
- Idle = status `idle` AND zero running agents (`AgentKind::Agent` + `AgentState::Running`).
- Kill only after `start_filetime(pid) == procStart`.
- Wait for the session to leave the registry: poll every 200 ms, give up after 10 s (`adopt_timeout`).
- Resume folder = first recorded cwd, captured from the live transcript before the kill.
- Confirm dialog copy (EN source): "End the Claude process outside the app and continue this session here? Command-line options given outside are not carried over; the app's settings are used. Background shell commands started by Claude may be stopped."
- No release is cut; the plan ends with a local build and a manual check.

## Review Focus

1. User types into the external terminal between the UI check and the click: backend re-check refuses with `adopt_busy` (Task 3 test `adopt_refuses_when_status_turned_busy`).
2. Session id changes inside an app terminal (`/clear`): the open view moves to the new id instead of showing the closed placeholder (Task 5 test `follows_new_session_in_same_terminal`).
3. Between "Move to app" success and the registry listing the session, the view shows the new terminal, not the Resume placeholder (Task 5 test `pending_terminal_wins_over_closed_placeholder`).
4. Pid reused by another process after Claude exited: kill refused (Task 2 test `terminate_refuses_wrong_start_time`).
5. Double click on "Move to app": second call refused while first is running (Task 3 test `adopt_refuses_concurrent_move`), button disabled while pending (Task 6 test `move_button_disabled_while_pending`).

### Task 5: View model (pure)

**Files:**
- Modify: `ui/src/components/Sidebar.tsx` (`View` type)
- Create: `ui/src/sessionView.ts`
- Test: `ui/src/sessionView.test.ts`

**Interfaces:**
- Produces:
  - `View` gains `| { session: string; tab: SessionTab; terminal?: number }` (old `{ session: string }` callers pass `tab`). `export type SessionTab = "terminal" | "info"`.
  - `export function openSessionView(sessionId: string, sessions: SessionCard[], terminalFor: (parentPid: number | null | undefined) => number | undefined): View` — in an app terminal → `{ terminal: id }`; else `{ session: sessionId, tab: "info" }`. Used by card click, History open, tray/toast navigate.
  - `export function resolveView(v: View, terminals: TerminalEntry[], sessions: SessionCard[], pending: ReadonlySet<number>): View` — follow-the-terminal rules:
    - `{ session, tab, terminal }` whose terminal now hosts a different session → same tab with the new id; hosts none → `{ terminal }`; terminal gone → `{ session, tab: "info" }`.
    - `{ session, tab: "terminal" }` (no terminal) whose session is now in an app terminal → `{ terminal: id }`.
    - Returns the same object when nothing changes (no re-render loop).
  - `export function tabBarFor(v: View, terminals, sessions): { sessionId: string; terminal?: number; active: SessionTab } | null` — null for a plain shell terminal and non-session views.
  - `export function moveState(card: SessionCard): { enabled: boolean; reason: "busy" | "waiting" | "agents" | "notMovable" | null }`.
  - `pending`: terminal ids created by Resume/Move whose session is not in the snapshot yet (App keeps it; entry removed once `sessionsIn` finds a session or after 15 s).
